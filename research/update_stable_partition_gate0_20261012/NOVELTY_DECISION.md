# Novelty decision: KILL

**Reject the generic thesis "update-stable hierarchy = persistent decisions +
local mutations + condition-triggered repartition" as an independent contribution.**
Confidence is high at this abstraction. The verdict does not reject all GTS++
work or an as-yet unspecified, genuinely different GPU physical mechanism.

## Cheap falsification test

Remove the candidate's new labels and GPU target, then substitute primary-source
state/actions for each component:

| Candidate component | Existing exact-metric control |
|---|---|
| Preserve historical partition decisions | EGNAT retains old memberships/ranges after a center is replaced |
| Admit sparse changes without immediate global organization | EGNAT nearest-center insertion; dsa-tree timestamped local insertion/deferred deletion |
| Retain exact queries despite historical decisions | EGNAT widens pruning by accumulated center displacement; dsa-tree accounts for temporal/fake-node history |
| Repartition only when accumulated quality/structure evidence requires it | EGNAT suggests repair when tolerance makes queries inefficient; dsa-tree evaluates fake-fraction thresholded subtree repair |

Sources: [EGNAT Sections 2–3.2](https://users.dcc.uchile.cl/~gnavarro/ps/is11.pdf)
and [dsa-tree Sections 3.2–3.3.1](https://users.dcc.uchile.cl/~gnavarro/ps/sccc03.pdf).
This is conceptual subsumption of the recipe, **not** a claim of identical
partitions, immutably fixed centers, or unchanged GPU code.

[Dynamic VP-tree Section 5](https://link.springer.com/content/pdf/10.1007/PL00010672.pdf)
also explicitly explains downward partition-change propagation and possible
global reorganization. Thus even the broad problem of disruptive radial-tree
updates is not newly identified. GTS's exact captured manifestation may still
be useful evidence, but useful diagnosis is distinct from a new remedy.

## Apply the declared gates without overstating them

| Gate | Assessment |
|---|---|
| KILL-1: one work covers every named dimension including the GTS manifestation | Near overlap, not asserted as literally proven. No reviewed paper measures GTS sparse churn and GPU consequences together. |
| KILL-2: different names, substantively familiar mechanism | **Satisfied** for the generic recipe; strongest ground for KILL. |
| KILL-3: classic mechanism ports unchanged and solves packed GTS | **UNKNOWN**, no port or same-contract experiment. Do not claim this stronger statement. |
| PASS-A: new measured GTS failure chain | Possibly distinct observation; insufficient to rescue a known remedy. Existing attribution also does not isolate a 90–92% causal fraction. |
| PASS-B: independent partition-identity mechanism | **Failed** at the present abstraction: history-preserving exact indexing already exists. |
| PASS-C: independent GPU-system co-design | **UNKNOWN**, none specified or tested. "On GPU" alone is not a difference. |

The attachment's absence-of-one-paper PASS formulation is not used to silently
lower the global novelty bar: different terminology or failure measurement does
not convert a subsumed mechanism into a new thesis. Uncertainty about direct
portability remains uncertainty, not either success or failure evidence.

## Strongest counterarguments and why they do not change this verdict

1. **GTS uses radial quantiles, not hyperplanes.** Correct. Dynamic VP-tree is
   radial, and history/thresholded repair is not new. A different radial repair
   invariant could be a new candidate, but it has not been specified.
2. **EGNAT changes centers and quality rebuilding is only suggested.** Correct.
   Its historical membership mechanism is narrower than immutable identity.
   dsa-tree supplies an evaluated exact-metric deferred-repair threshold. We
   reject the broad recipe, not claim a completed optimal stability controller.
3. **CPU metric trees do not solve packed GPU rebuild/plan work.** Correct and
   untested here. An independent cross-layer mechanism might exist, but adding
   parallelism, buffering or another threshold is not automatically one.
4. **Near-global GTS churn is newly measured.** It is a scoped observation worth
   preserving. Measurement/causal characterization can support a different
   mechanism; it does not alone establish a non-incremental algorithmic remedy.

## Three distinct decisions

- **Implementation:** none built; no correctness/performance admission.
- **Mechanism:** current generic recipe conceptually overlaps prior work.
- **Thesis impact:** stop this stable-partition core novelty claim; retain GTS
  diagnosis and other contributions. Do not rewrite previous results as useless.

**Reopen condition:** specify a non-incremental mechanism with a clear state,
invariant, physical work removed and added search cost, demonstrate that the
nearest controls do not establish it, and predeclare a decisive reproducible
same-contract test. No implementation or GPU run is part of this Gate 0 closure.
