# Gate0: novelty boundary before the integration campaign

Classification: **ENGINEERING_ONLY**, not a new static-query or dynamic-system thesis.

[PDX, SIGMOD2025](https://ir.cwi.nl/pub/35044/35044.pdf), abstract and sections2–5, already combines exact dimension pruning with access efficiency; PDX-BOND avoids data transformations and explicitly motivates frequent updates. Its evaluated CPU/block-vertical setting differs from this raw-row-major GPU range request, but a processor port and cheap flat-store mutation do not alone establish a non-incremental mechanism. The original BOND work cited as reference13 in PDX must also be checked before any eventual novelty admission.

Gate2's UCR/VA-file/GPU-compaction precedents remain binding. This bounded test asks only whether the unchanged native update/kNN path and frozen progressive range implementation coexist correctly and retain complete-workflow gains. It may reject that compatibility hypothesis, not prove novelty. No paper drafting or broad/new search direction is authorized. A positive gate still needs an explicit sidecar retaining the nearest prior art and missing same-contract external evidence.
