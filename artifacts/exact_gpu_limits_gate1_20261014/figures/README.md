# Figure captions and visual contract

All figures are authored at3.5-inch final width, use print/grayscale-safe
redundant marks, contain no invented error bands, and ship PDF/SVG/400-DPI PNG
with exact CSV data. The CDF is a complete finite population; the other charts
are conditional algebra, so sampling confidence intervals would be misleading.

1. **required_dims_oracles:** Free query-global ordering removes most of the
   original-to-pair-oracle coordinate-count gap on all32M pairs. Counts include
   hits at960; guarded and ordinary counts coincide. Log-coordinate x-axis;
   this is not actual GPU traffic, a deployable ordering or a universal bound.
2. **metadata_rejection_pareto:** The frozen eager-metadata/full-raw-fallback
   plane reaches keeper equality at73.60%–80.24% safe rejection, below the
   proposed90% barrier. The line is not an achievable representation frontier;
   strict improvement requires rejection above the equality line.
3. **lambda_window_heatmap:** Only beyond the ideal uncapped Poisson keeper
   contour can whole-database sharing beat the frozen range-source reference.
   The frozen5000qps/500us corner stays above it. Other analytic winning regions
   are retained, not executed. Collection time is not complete latency/SLA.
4. **design_space_map:** Known/conditional payload costs do not establish a
   physical lower-left frontier. X is extra indexed payload beyond common raw
   FP32 storage, not update latency or all runtime allocation; y is source
   payload, not NCU DRAM. Batching is the5000qps/500us uncapped model. The INT8
   segment varies F from0 toN in its algebra; F=0 is unrealized, not a correctness
   pass. The compact-metadata curve assumes f=90%, not observed rejection.
   Tree/index costs are explicitly unpriced rather than placed at fabricated
   zero coordinates. Update and workspace unknowns remain in SYSTEMS_TABLE.
