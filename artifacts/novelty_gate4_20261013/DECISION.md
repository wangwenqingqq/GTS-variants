# Gate4 decision — NO_DISTINCT_MECHANISM

## Q1 — Which candidate is not subsumed?

**None of these three concrete candidates demonstrates the required distinction.**
M1 fails its physical-traffic opportunity screen without implementation. M2 is
an interval lower-bound screen with raw exact refinement. M3 changes a partial
distance primitive's threshold source for kNN; an actual shared range/kNN core
is in pinned Faiss source (matrix S04/S12). BOND/PDX already cover its underlying
partial-distance kNN principle. A CPU/GPU platform change is not, by itself,
a non-incremental mechanism under this contract.

This is not a universal absence-of-novelty proof. M1's unexplored latency/cache
scheduling effects and all genuinely different representations remain unknown.
Only the frozen candidates are closed; no encoding or layout search is authorized.

## Q2 — Does the mechanism address the measured bottleneck?

M1/M2 target raw-coordinate bandwidth diagnosed by Gate2. M3 targets Gate3's
dominant kNN query component. This makes them relevant hypotheses, not novel or
performance-qualified mechanisms. No Gate4 dynamic DRAM/latency measurement was
made and no initial-snapshot count is extrapolated to the full mixed service.

## Q4 — Does a same-semantics external comparator exist?

Exact-search methods/code exist: BOND/PDX-BOND/VA-file, CPU Faiss Flat/Panorama,
and GPU exhaustive scan. They are **not all prequalified implementations of this
numeric/output/update contract**. Range specializations in the matrix are marked
derived; CPU/GPU timing panels must remain separate. Numerical boundary handling,
full outputs, query setup, selection, updates, maintenance and release require
qualification before a same-contract external claim. No such comparison was
executed because no novelty-admitted winner exists.

## Q5 — Final label and action

`NO_DISTINCT_MECHANISM`. No candidate is promoted; all three are closed for this
thesis-admission round. There is no external run queued and no GPU kNN kernel.
Retain the strong exact GPU range operator/engineering study and the parent
static/dynamic evidence without changing Gate3's **UNCLASSIFIED** result.
Do not keep packaging this realization as a new GTS++ index/system thesis.

### Reopen conditions

1. State a specific non-incremental mechanism not reduced to known pruning,
   interval refinement, blocked layout, query-type substitution or compaction.
2. Bind it to the measured bottleneck and establish a sufficiently large,
   charged headroom/cost advantage, exact semantics and an external comparator.
3. Freeze a new campaign before implementation. Demonstrate the declared
   structural external advantage under same-contract qualification, not a
   small internal/kernel speedup or changed query mix.

No theorem of representation impossibility, external superiority, dynamic kNN
benefit, maintenance advantage,1B scalability or100k-event sustainability is
established by this round.
