## Interpretation and admission boundary

The engineering effect is strong under the declared same-campaign events+release denominator. Ordinary safe CUDA batching lowers Host API counts but leaves fine-grained row-copy activities;FINAL changes execution granularity. W2 has zero dependency edges and zero eliminated row assignments,so it does not establish a new ownership algorithm or payload saving.

DRAM counters are unavailable,not zero. FINAL-only update-kernel L2 counters exclude metadata and native copy-engine traffic. CPU core-seconds fall,but event-window average CPU consumption remains roughly one core-equivalent;instantaneous utilization and pure computation/wait fractions are unresolved. Small insert regressions,query uncertainty,finite tails,shared Host-resource interference and later-phase calibration are retained. Known owned allocation is not instrumented absolute peak memory. Novelty,production,Graph,concurrency,other architectures,1B vectors and build-inclusive process wall time are not admitted.
