# PCA 剪枝的 4090-left 百万点端到端测量（2026-09-25）

在 4090-left 的 RTX 4090 上，将 64 维 PCA 投影作为精确 L2 扫描前的拒绝过滤器。F 是原有的全量精确扫描并每 32 个原始坐标提前拒绝；P32/P64 先读取预计算的 PCA 投影距离，未被排除的点再执行与 F 完全相同的原始向量距离和结果写入。三种模式位于**同一编译二进制**，保留同一棵 GTS 树、`id_list` 顺序、CUDA Graph、删除映射、固定容量 host 结果交付。投影索引在建树后加载、按 `id_list` 顺序转为按投影维度排列；P32/P64 均使用同一份 64 维索引。

每个进程预热 8 个查询，再计时固定的 8 个查询；四个独立进程轮次交错 F/P32/P64 的顺序，并在奇数轮反转数据集顺序。表中是每轮 8 个**完整热查询**（Graph 启动、同步、固定容量结果返回主机）的均值，再取四轮中位数。F/PCA 加速比采用同轮配对比值的中位数。

| 数据 | F | P32 | F/P32 | P64 | F/P64 |
| --- | ---: | ---: | ---: | ---: | ---: |
| GIST 1M×960D | 115.887 ms | 87.573 ms | 1.321× | **77.657 ms** | **1.489×** |
| Deep 1M×96D | 16.951 ms | 16.263 ms | 1.042× | **10.912 ms** | **1.551×** |

P64 在两数据集均 4/4 轮快于 F；GIST 四轮 F/P64 比值为 1.501、1.495、1.481、1.483，Deep 为 1.562、1.543、1.552、1.551。相对 F，P64 热查询延迟分别下降约 **33.0%** 和 **35.6%**。这些数值不能与先前 PRO 6000 上 F 的 98.069/15.136 ms 直接横比；本表的基线和实验都在 4090-left 上重新测过。

**索引成本与适用范围。** 每百万点的 64 维 float32 投影文件为 256 MB；当前原型在 GPU 同时保存原点顺序和按查询扫描顺序转置的两份投影，共约 512 MB。4090-left 的 CPU 投影构建（含该脚本的输入/输出 SHA-256）耗时 GIST **4.234 s**、Deep **0.726 s**。P64 比 F 多出的设置时间中位数约为 GIST **0.192 s**、Deep **0.178 s**。按测得的每查询节省时间估算，摊平“构建 + 额外设置”大约需要 **116 个 GIST 查询**或 **150 个 Deep 查询**；当前只有 8 个查询的一次性任务，把 PCA 构建算进去是**负收益**。这只是摊销估算，尚未测索引更新后的维护成本。两模式在这个诊断驱动里都先构建同一棵 GTS 树，建树本身不在热查询计时中，也没有为 F 或 P64 取消建树。

**正确性。** 24 个正式计时进程的全部 192 个查询输出，均与 CPU 校验过的原版 count 和完整有序 float32 哈希一致；同轮 F/P32/P64 的逐查询结果也完全相同。普通半径下两数据集各 8 查询的门槛、P64 的 memcheck 和 synccheck，以及 Deep 的零半径、全命中和负半径空结果均通过。每次启动先确认空闲卡，运行中监测其他 GPU 进程。投影基由 float64 正交分解产生，主成分正交误差 <3e-15；GPU float32 下界使用 `radius+0.01` 的保守拒绝门槛并经上述固定工作负载输出验证，但**尚未给出任意输入/半径下浮点误差的形式化上界**。
