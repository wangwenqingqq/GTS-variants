# 单 PCA 方向、单 bit 树叶过滤的离线筛选

对象是现有 GTS 树的 100,000 个非空叶子，每叶 10 点，以及与 PCA 端到端实验相同的 GIST/Deep 百万点数据、8 个查询和正常半径。读取 `pro6000-8` 的实际树快照、`4090-left` 的 64 维 PCA 投影；两个主机上的数据源 SHA-256 一致。计算脚本见 [screen.py](screen.py)，逐查询计数与输入哈希见 [EVIDENCE.json](EVIDENCE.json)。这是 CPU 离线筛选，未实现 GPU 内核，也没有测端到端延迟。

一个安全的单 bit 超平面判定可令 `b(x) = [p_j(x) >= t]`。当 `p_j(q) > t+r` 时，只有 **整叶所有点** 满足 `p_j(x)<t` 才能剪叶；反侧同理。异号本身不是安全拒绝依据，因为两点可能紧贴阈值。固定采用第 1 主成分的全局中位数作阈值，对这 16 个查询均剪掉 **0** 片叶。

为了给单 PCA 方向的 bit 一个偏乐观的上界，进一步允许**每个查询**从 64 个轴任选一个、任选一侧，并针对该查询临时选最佳阈值。这样，一个轴最多剪去 `max(count(leaf_max < q_j-r), count(leaf_min > q_j+r))` 片叶；真正预存的固定 bit 不可能比它更强。该筛选用真实叶内 10 点计算极值，并且未给浮点误差留保护余量，因此也偏向高估可剪数量。

| 数据 | 固定 PCA1 中位数 bit | 理想单轴 bit 平均可剪叶 | 理想单轴 bit 最多可剪叶 |
| --- | ---: | ---: | ---: |
| GIST 1M×960D | 0 / 100,000 | 3,634 / 100,000（3.63%） | 10,714 / 100,000（10.71%） |
| Deep 1M×96D | 0 / 100,000 | 0 / 100,000 | 0 / 100,000 |

因此，在这些查询半径和当前树结构下，**一条 PCA 超平面产生的一个 bit 不足以排除大多数无关叶子**。这不否定多个 bit、其他数据依赖型划分或带浮点区间的多维节点下界；那些是不同索引设计，需分别测构建、访存、剪枝与端到端延迟。此前 P64 的逐点过滤把 64 个连续投影坐标的距离累加起来，不能由一个符号 bit 直接替代。
