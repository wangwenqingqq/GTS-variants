## 2. 固定任务与边界

- 数据：GIST 1M×960D、Deep 1M×96D；沿用记录中的原始 float32 文件、内容散列及 ID，禁止私自归一化、量化、降维。
- 查询：静态、库内、自身允许参与的 L2 kNN。self-inclusive 表示自身有参赛资格，不表示在有至少 K 个同距重复向量时，必须强制把自身 ID 插入答案。
- K：8、32。B：1、32。共 8 个正式形状，不引入范围半径作为外部输入。
- 输出：每条查询恰好 K 个合法、互不重复的原始 ID，及对应非负有限 float32 欧氏距离；按距离非递减交付。无需恢复旧范围实验的 GTS `id_list` 顺序。
- 数据和索引已驻留 GPU 时的完整 Host-ready 查询耗时是主指标。载入、布局、训练／建索引、Graph 捕获另记，不能声称这是含构建的整应用加速。
- 沿用同一物理 RTX PRO 6000 Blackwell；使用已授权的空闲 GPU，核实 UUID 和 NUMA，而不是仅依赖容易变化的 GPU 序号。保留独占 admission 和监控，不停他人服务、不改时钟或功率。
- 不研究在线排队、动态更新、多 GPU、PCA、新图结构、压缩精度或新的任务压缩器。

## 3. 优化版缺口：这次明确实现三个入口

| 名称 | 新路径 | 目的 |
|---|---|---|
| `O_FULL` | AoSoA32＋查询微块共享＋全表 FP64 平方距离＋GPU top-K | 最小可运行优化版，无需树或外部半径；率先补齐比较中缺的行 |
| `O_BOUND` | 实时种子上界＋同一共享核验＋安全提前停止＋GPU top-K，不走树 | 继承早退，隔离上界和早退的净价值 |
| `O_MASK` | **与 O_BOUND 完全相同的种子与上界**＋浅层树／父枢轴复用＋原布局掩码核验＋同一 GPU top-K | 本轮主候选；隔离树相对无树优化路径的额外价值 |

### 3.1 必须先做 O_FULL，不能把范围函数改名就交付

查询不接收 oracle 半径。扫描全部对象，在 GPU 上选出 K 个距离最小者，仅把最终 K 个结果交给 Host。距离和排序 key 在 top-K 完成前保留 FP64 **平方距离**；不能先用旧 `raw_distance` 中的 float32 `sqrt` 结果排序，因为这样可能合并不同的近邻距离。

第一版允许物化 `B×N` 的 FP64 平方距离数组：B=32、N=1M 约 256 MB，显式记 workspace。选择阶段采用经过验证的 GPU 分块 top-K／归并或相应高效选择器；同一选择后端用于三个自有模式。全排序可作正确性参考，若初版用全排序计时，必须标成该实现，不能因它很慢就概括检索机制无效。不要先传回 N 个距离让 CPU 选 K。

分块 top-K 合并要采用一致比较规则：参考平方距离优先、原始 ID 用于自有确定性打破并列。在每块取 K 再从各块结果合并取 K，不丢失全局前 K。所有选择和归并成本计时。

### 3.2 O_BOUND：运行时取得安全阈值，不向 oracle 借答案

首版固定一个简单初始化方式，不搜索最有利种子：数据库中以固定随机种子选 `M=min(4096,N)` 个互不重复原始 ID，M≥K，清单与查询选择无关并提前冻结。每个查询到来后，**在计时内**计算这 M 个对象的参考距离、选择其中第 K 小平方距离，记作 U_sq。

例：要找最近 8 个，已检查的 4096 个真实对象中，第 8 小平方距离是 0.81。因为已经有 8 个合法对象的平方距离不超过 0.81，全库真正第 8 小参考平方距离不会大于 0.81。这个上界可能很松，但不因松而漏答案。

后续完整覆盖全部对象；以原 FP64 维度顺序累加，每 32 维检查，部分和 **严格大于** U_sq 才拒绝。保留等于阈值的对象，再在所有幸存者中选 K。种子集只用于求阈值，不单独追加一遍输出；最小实现允许主扫描再次计算种子，重复成本真实计入。

不以 ANN 返回的 K 个候选代替全库覆盖，不直接使用真第 K 近距离，不把前一查询／oracle 的结果作免费上界。首版不维护复杂的跨块动态阈值更新；上界质量差的结果也必须保留，不能在 final 集上临时换成更聪明的种子。

### 3.3 O_MASK：必须同时处理“平方阈值”和“树的几何半径”

GIST 固定 C4、Deep 固定 C1；复用经过核对的树拓扑、成员和保守区间。把实时阈值用于生成可靠候选掩码，再沿原 AoSoA32 布局核验。B≥2 的查询微块 QT=2，B=1 对应 QT=1，尾部查询须正确掩蔽。不引入 C_TASK。

重要数值边界：旧范围函数接收 float32 半径，新 kNN 得到的是 FP64 平方阈值。**不能简单 `float(sqrt(U_sq))`，再平方，把向下舍入的半径用于剪枝。**对象早退直接与 U_sq 比较；树前端用明确向外的半径／距离包围，且要证明相对于被冻结的 FP64 距离判定不会漏掉边界。

严格来说，单次 sqrt 向上舍入还不足以自行证明“数学三角界”和“顺序 FP64 平方和”的一致性；还须考虑距离累加误差。新增转换 helper 必须附上误差包围的推导与测试。没有可靠界的节点应保守保留；不能用一个经验 epsilon 宣称精确，也不能把全放行退化路径包装成有效剪枝。

小数据独立参考必须确认：全局前 K 对象没有被树掩码排除，等距边界候选没有被错误截断。已有 range 审核不能替代新阈值接口的正确性证明。

### 3.4 移植接口建议

## 4. 对手：原生 kNN，不能继续使用有容量截断的范围适配器

### 4.1 六个完整候选路径

1. `GTS_ORIG`：当前已通过复核的 original V2 full-ID 适配器。保留原算术、分配、排序及 1 GiB workspace。计时内全部实际动作保留。新二进制散列不同就重测，不冒充历史二进制。
2. `O_FULL`。
3. `O_BOUND`。
4. `O_MASK`。
5. `FAISS_FLAT`：真实 `GpuIndexFlatL2.search(K)`。Faiss 官方指出全探桶 IVFFlat 回到穷举，Flat 是必要的直接参照；不能只挑一个慢的全桶 IVF。
6. `IVF_ALL`：原生 `GpuIndexIVFFlat`，固定 `nlist=nprobe=1024`，无 PQ／半精度存储，无额外限制扫描的 cap，核实 ntotal、所有 ID 恰好入桶一次。这次从第一轮就与其他模式轮转测量，不再事后单独补测。

以上“完整路径”描述覆盖方式，不自动保证与参考算术对所有输入等价；实际召回和距离字段仍必须审核，失败不能进入同质量速度结论。

### 4.2 CAGRA 和部分探桶 IVF 的质量—延迟轨

现在任务就是 K8/32，直接让它们返回 K8/32，不再使用 K1024/2048 后按固定范围过滤的 P6 适配器。

CAGRA 首先沿用可运行的 cuVS 原生后端：图度数64、中间图度128，搜索 `AUTO`；开发小网格 `itopk_size={64,128,256,512,1024}`、`search_width={1,2,4}`，只运行冻结版本确实支持的配置。不硬卡低 max_iterations；记录实际默认／自动设置。主要调搜索预算，不重新开建图算法搜索。

Faiss-IVF 开发 `nlist={1024,4096}`，`nprobe={16,64,128,256,512,1024,2048}` 中合法项；另外固定 1024/1024 完整控制。训练样本20万、固定种子；训练仅用数据库，不用最终查询的答案。

按每个数据集/K/B 的开发质量，冻结达到 99%、99.9%、100% 的最快配置；选择器是两次完整开发 pass 的均值，不选最好单次。100% 只是“开发集观察到零漏检”，不能命名为精确图。一个配置满足多个 anchor 时只运行一次、多个标签引用，避免重复样本。

测试未达到冻结目标时，报告 miss；不继续调 nprobe，不换查询，不换质量定义。若开发没有达到某个目标，该锚点记录不可达，可保存最高质量点但不能冒名填充。

## 5. 统一质量合同，不再把不同任务／不同精度混成一张加速表

### 5.1 参考与主规则

独立全表 GPU FP64 oracle：float32 输入提升为 float64，按维度显式 RN 减法、平方、累加，FMA 关闭。保留参考 `(squared_distance, original_ID)` top-K 及真实参考距离完全相等的 kth 边界集合；做独立 CPU 抽检，小规模全部 CPU 枚举。

跨方法主质量指标沿用已登记的 **tie-aware ID Recall@K**。tie 是参考平方距离真正相等，不是落在任意 epsilon 内。所有方法必须返回恰好 K 个不同有效 ID，没有非法槽位、NaN、负距离或截断，并记录完整查询比例、每查询召回、最差查询和确定性 ID 召回。允许边界合法替代，但不能遗漏严格更近的对象。

所有完整模式：每条查询都要达到 tie-aware100%，不能只四舍五入显示总平均100.000%。自有三个模式另核查确定性 ID 与参考是否一致。self-only 对质量的影响使用单独、清楚定义的附表，不能改变主合同。

返回字段沿用原 kNN 合同：`|delivered_distance^2 - reference_squared| <= 5e-5*max(1, reference_squared)`；同时单列绝对误差、纯相对误差、零距离误差、负值和排序检查。这个容差只作用于字段，不用于放宽候选成员或定义 ties。第一版不要求外部 FP32 与自有 FP64 位级一致。

### 5.2 不把经验100%等同于完整性证明

分别记录 `coverage_status`（全库穷举／安全排除／近似探索）和 `tested_quality_status`。CAGRA 在最终集100%时应诚实展示其时间，不能隐藏，但只能称经验零漏检。外部全库计算也可能发生浮点近邻边界错误，不因“exhaustive”就跳过审核。

### 5.3 精算是单独模式，不偷换结果

主外部轨先测 native K 输出。若另加 R>K 候选精算，必须命名独立模式，记录 R、精算和选择时间；原生搜索时间不能配精算后的质量。只重算已经返回的 K 个，不能找回遗漏的更近对象。禁止把候选重算描述成全库精确保证。

### 5.4 逐轮资格

每一轮、每个方法、每个 K/B 都审核真实交付结果；不能仅使用第一轮 recall 配六轮时间。固定并复用已建索引，核对索引哈希；无法保存设备索引时，固定构建规则并逐轮审核，注明图构建变化。对所有新优化路径单独跑 memcheck、synccheck；既有测试只在原范围内有效。

## 6. 统一计时：只算“同样 K 个答案已交付”

### 6.1 主口径

输入起点：这批库内查询的 host ID 列表已就绪，数据库／索引驻留 GPU。begin 到每条 K 个 ID＋float32 欧氏距离已落在 Host 且必要同步完成为止。

计时包括：输入复制／查询向量 gather、类型转换、上界种子计算、树遍历、掩码生成、距离核、GPU top-K／归并、原生 squared→Euclidean 转换、最终格式转换、D2H、同步、查询内分配释放与失败回退（若有）。

不计：读文件、静态数据／布局构建、训练建索引、加载缓存、Graph 捕获、预热、oracle、答案审计、报告写盘。公开这些冷成本、额外显存及缓存依赖，不将原始 baseline 的 setup 加入而排除自有 setup。

所有程序使用一个连续总 pass 计时，不使用“另一次 kernel 时间＋离线 CPU 排序时间”的拼接。每批准备和结果格式动作都放在同一个计时范围内。若本轮必须继续使用某个 Python native 接口，实际 Python／转换成本计入并单独记录；主比较优先使用 C++／C API 或真实支持的 GPU 指针，避免人为强制候选 D2H 再 H2D。Faiss 官方允许 GPU 指针用于 search，但必须正确同步实际库 stream，不能只同步一个不相干的默认流。

### 6.2 输出顺序与传输

kNN 按距离交付，不按旧 GTS 数据布局排序。相同距离按各模式合法规则处理，确定性策略另报。主机结果类型统一 ID int32（N≤1M）和 float32 欧氏距离；库输出int64→int32的实际成本应计时。不得强制自有版本与外部使用同一种内部布局。

B=32、K=8时有效ID＋距离载荷为32×8×8=2048字节（不含少量元数据）。这个任务已经没有此前大范围输出的容量差异。

### 6.3 统计

正式每形状六轮，各模式新进程，轮转顺序；保证某方法在对手前／后均有出现，保存实际顺序，不能称任意轮转都严格达到全部成对平衡。六个完整模式可使用预先冻结的反向对称顺序表；ANN重复配置去重后另生成完整的平衡表，不临时按速度排序。

每进程同256查询、相同批次成员、2个固定开发预热批次，必要时延长预热需在正式前统一冻结。B1与B32是同一顺序的嵌套划分。每方法每轮只统计完整pass，保留每batch延迟。

报告六轮总时间、总时间中位数、配对比值的log均值／95%区间／wins、按运行顺序拆分的结果；不能拿“中位数之比”冒充“配对比值中位数”。CI仅反映所测查询／进程的波动，不证明未来分布。

主指标：256条查询总Host-ready毫秒。辅指标：GPU-ready、batch p50/p95、QPS、总耗时/Q。**总耗时/Q是摊销成本，不是批量里每条请求的响应延迟。**

## 7. 查询集与阶段安排

### P7.0：身份和正确性

复用已有32条seen查询完成桥接，固定 O_FULL/O_BOUND/O_MASK 的源／二进制身份。小数据建议 N4097、D96/960、K8/32、B1/32，并覆盖33查询尾批、重复向量及kth并列、全零／近零／大有限值、种子上界很松、U=0、树全放行与高拒绝率。

必须检查：top-K根据FP64平方key排序；树和早退不会排除应有邻居；完整pipeline输出符合合同。新代码有错先修，不给错误模式出速度结论。

### P7.1：一张真正有优化版的最小表

**GIST 1M×960D、K8、B32、32条已见查询、三轮交错。**

模式：GTS_ORIG、O_FULL、O_BOUND、O_MASK、FAISS_FLAT、IVF_ALL，再加一个合法的高预算CAGRA诊断点（例如itopk1024/search_width4/AUTO，记录是否符合实际版本）。这是7模式×3轮=21个查询计时进程，不含构建和oracle。

先交完整时间／质量表，不要求每个优化组件都获益。CAGRA的诊断点不自动作为正式冻结最优点。若 O_MASK 未过正确性，O_FULL 的结果仍可作为部分交付，但整轮“组合优化版比较”仍标未完成。

### P7.2：开发并冻结

已有 native kNN dev128用于调试和受限参数选择，原 final256降为已见回归集；旧100% anchor失败记录保留，不覆盖。自有布局/QT/检查周期/深度/种子M不搜索；用相同固定参数让实现优劣真实暴露。Faiss/CAGRA按第4节搜预算，冻结各形状的有效前沿。

新最终集：每数据集256条，固定新种子，排除 P0–P6、此前 native kNN 的dev/final、所有已见32条及本轮开发ID；保存完整排除集摘要、碰撞检查和qid散列。冻结全部实现／配置之后再生成；不挑低命中或容易查询，不用final调种子。

### P7.3：正式完整对照

2数据集×2K×2B×6完整模式×6轮＝**288个完整模式进程**。

全桶IVF和GPU Flat从首轮参与，避免再次只能给事后非配对比较。O_FULL/O_BOUND/O_MASK全部保留，不仅报最终最优的一个。若论文只需一个自有配置，必须在开发集事前冻结，不能用final按行取最优宣称无需选择成本。

### P7.4：ANN质量—时间确认

各形状对CAGRA和部分探桶IVF，执行开发冻结的99%／99.9%／100%最多三点，重复配置去重，每点六轮。上限8形状×2家族×3点×6轮＝288进程，通常因配置重复或锚点不可达而减少。无需增加数据集、K1024或大规模图参数搜索。

在同一个总campaign里把这些模式与完整轨轮转，确保要作同质量时间比的模式实际在同轮；不存在合格同质量点时只画质量—延迟前沿，不输出“同质量加速”。

## 8. 主瓶颈归因：少而关键的独立测量

预先取32条开发查询，在GIST K8 B32上分别剖析：GTS_ORIG、O_FULL、O_BOUND、O_MASK、FAISS_FLAT、IVF_ALL、冻结的CAGRA高质量点。范围只包含一个post-warmup查询pass，不带建图或训练。正式计时不开profiler。

| 阶段 | 时间／工作量 |
|---|---|
| 初始化上界 | 种子gather、4096配对的距离与第K小选择；U相对真kth的松紧只在离线分析 |
| 索引处理 | 枢轴距离、访问节点／桶／图扩展及候选数量；仅记录实际可取得的计数，不猜测 |
| 核验 | 实际配对坐标更新、共享读取步数、warp最长路径、DRAM字节／访存请求、FP64/FP32指令 |
| top-K | 局部选择、合并、排序与临时矩阵读写；不要继续假设它必然很小 |
| 交付 |最终K条的格式转换、D2H和同步；API等待与GPU执行不重复相加 |

如果只是O_FULL赢原始GTS，但O_MASK不赢O_BOUND，结论是执行基础改善而非树带来新增优势。如果新top-K成为大头，就接受breakdown变化，不继续围绕旧距离阶段的比例宣称主瓶颈。

机制归因首轮只需O_BOUND/O_MASK同一数值、种子、选择器对照；需要进一步拆开masked kernel形态时，在小开发集复用P5全有效／真实掩码干预，不把人工更慢的TREE_ALL用作对外加速分母。

## 10. 停止与决策规则

| 观察结果 | 本轮决定 |
|---|---|
| O_FULL正确且比原始GTS快 | 补齐总改善的第一笔账；仍须看外部Flat，不直接称竞争领先 |
| O_MASK稳定超过O_BOUND | 保留树在kNN里的独立新增贡献；否则保留范围正向证据但不能外推到kNN |
| 胜原始但不敌Flat或全桶IVF | 公开全部结果，将原因定位到当前主要阶段；不为大倍数选择弱分母 |
| CAGRA测试集零漏检且更快 | 保留这一强竞争结果，并明确经验质量与完整保证的区别 |
| 冻结100%配置在final失败 | 失败保留；不得调参补救冒充原结果，新增实验应独立登记 |
| 种子上界松、几乎没有剪枝 | 记录阈值、工作量与收益；本轮不无限搜索种子，只证明当前方案的真实效果 |
| 正确性/越界/未授权设备失败 | 停止该模式有效计时，保留失败；无效结果不算性能负面证据 |
| 只有baseline复核，没有O_* | 整体任务未完成；明确pending，不以其他更多benchmark代替 |

不预设必须提升多少倍；优先级仍由主导成本和强对照决定。任何约3%或10%的研发分界只能用于是否继续调优，不是论文录用标准。
