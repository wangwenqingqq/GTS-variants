# Strict numerical contract

The oracle reads the stored float32 values, converts each operand to float64, then performs subtraction, multiplication, and an increasing-coordinate sum with round-to-nearest-even at each step. It compares the squared sum with `double(radius) * double(radius)`, including equality. GPU code uses explicit `__dsub_rn`, `__dmul_rn`, and `__dadd_rn`; the independent CPU check is compiled with contraction disabled. The 4096-point boundary fixtures compared all 98,304 CPU/GPU pairs bit for bit.

For the fast screen, let `u = 2^-24` and `gamma_k = ku/(1-ku)`. With normal finite intermediates, float32 subtraction and multiplication each contribute at most `u` relative error; positive sequential accumulation contributes at most `gamma_(D-1)`. The corresponding float64 path has unit roundoff `2^-53`. For `D <= 960`, `eta = 4 * gamma_(D+2)` conservatively exceeds the combined ratio error between the float32 sum and the specified float64 sum. The kernel detects subnormal, zero-underflow, overflow, and nonfinite float32 intermediates and uses the reference path for them. It rejects only when `sum_fast > radius_squared * (1 + eta)`. Every item not safely rejected is evaluated by the FP64 reference path; every emitted distance comes from that path.

Tree metadata is rebuilt without changing the topology, pivot IDs, or members. For each node, every covered point contributes a pivot distance. Float64 accumulation error for 960 coordinates is below `1.1e-13` relative under the normal-range model. The rebuild widens each norm with `1e-10` relative and `1e-12` absolute margins and moves the endpoints one representable float64 value outward. Query-pivot distances use compatible intervals, including the fast screen's `eta` when applicable. A subtree is pruned only when its distance intervals are separated by more than `radius * (1 + 1e-10) + 1e-12`. Thus a float64-reference hit cannot be excluded by an unadjusted old `min_dis` boundary.

This is a contract for the specified FP64 operation sequence, not a claim about exact real-number L2. The direct FP32 arithmetic replay is an equal-work cost experiment; its output is not used as an exact oracle or in the strict six-mode result table.
