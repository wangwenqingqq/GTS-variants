# 百万点 L2 叶层提前拒绝实验

按节点把遍历分配到多个 CTA 只解决原来一个 512 线程块串行扫最后一层的问题。固定这项遍历改动、跳过融合路径中无用的重复计数、结果融合及 CUDA Graph 后，本实验只改变叶节点距离计算：Q 是原通用叶算子；H 用相同逐坐标顺序做完整 L2 距离，隔离指标专用化；J 在 H 上每 32 维检查部分平方和，超过保守阈值 `(r+0.001f)^2` 的点立即拒绝。命中点仍按原顺序累加并输出原 float32 距离。

| 数据集 | Q 原叶算子 | H 完整 L2 | J 提前拒绝 | Q/J 完整查询收益 |
| --- | ---: | ---: | ---: | ---: |
| GIST 1M，960 维 | 407.405 ms | 407.479 ms | 317.720 ms | **1.282×**（4/4） |
| Deep 1M，96 维 | 48.425 ms | 48.489 ms | 45.939 ms | **1.054×**（4/4） |

数字是 GPU 4 上四个独立进程轮次的中位数；每进程预热 8 次、测量 8 个固定查询的均值，交错顺序为 QHJ、JHQ、HJQ、QJH，并在奇数轮反转数据集顺序。计时涵盖 Graph 执行、同步及固定容量 host 输出拷贝，不含索引构建。Q/H 在两套数据上都基本持平；GIST H/J 为 1.283×，Deep H/J 为 1.056×。因此静态资源报告中原通用叶算子的 47,528 B/线程栈需求并没有单独产生可测收益，新增收益与提前拒绝相符。

原因是树界在高维大规模数据上几乎没有排除叶节点：8 个普通半径查询的候选叶数，GIST 为 91,892–98,738/100,000，Deep 为 99,553–99,976/100,000。叶层仍需处理近乎所有点，而大量点最终在半径外。GIST 维度多，提前停止能省下足够的坐标计算；Deep 只有 96 维，节省较小，分支检查本身也有成本。这个优化减少的是点距离无效工作，不能把它描述成索引剪枝能力变强。

Q/H/J 在两套数据的普通半径下，各 8 个查询的完整有序结果文件 SHA-256 完全一致，并与独立 CPU 校验过的原实现 count/有序 float32 哈希一致。J 在两套百万点数据上的 memcheck、synccheck 均为零错误；零半径、全命中半径、负半径空结果也全部通过相同输出检查。四轮每次运行均有空闲卡准入和外部进程监测。完整逐轮数据、40 个收据哈希、二进制哈希见 [EVIDENCE.json](EVIDENCE.json)，本地原始运行记录保存在忽略的 `local/audited_gpu4/`。

这只是固定 Q 路径上的增量完整查询收益；原始单块遍历、结果融合或 CUDA Graph 的旧实验与本次使用不同二进制和轮次，不能把各自加速比相乘作为已测累计收益。生产代码未改动，阈值与正确性结论限定于本实验的 float32 L2、正的普通半径及上述边界用例。
