# 百万点负载：正交投影下界筛选（2026-09-25）

问题是当前单枢轴、树层次的度量下界不能充分区分候选点。这里直接测试一个非枢轴的**安全 L2 下界**：从数据中随机抽取 8192 个训练点，求前 `k` 个正交主成分 `P_k`；对查询和点预计算投影后，以 `||P_k^T(q-x)||₂` 作下界。因为 `P_k^T P_k=I`，该值在精确算术下不超过原始 `||q-x||₂`。脚本使用 float64，并逐点检查投影下界不超过真实距离。实际 GPU 浮点实现还需保守舍入裕量才能保证不漏报。

实验使用 GIST 1M×960D 与 Deep 1M×96D 的原查询半径和固定 8 个查询。每数据集另抽取与训练集不重合的 20,000 个测试点，共 160,000 对查询-点。当前 GTS 树已访问 GIST 91.9%–98.7%、Deep 99.6%–100% 的叶，因此这里筛选的是适合绕开树的精确扫描路径；它不是逐个候选叶的重建树实验。

| 数据 | 下界维度 | 实际应排除 | PCA 安全排除 | 原坐标前缀同维度排除 | 索引 float32 估算 |
| --- | ---: | ---: | ---: | ---: | ---: |
| GIST | 16 | 146,909/160,000 | 92,895 (58.1%) | 50 | 64 MB |
| GIST | 32 | 同上 | 108,804 (68.0%) | 110 | 128 MB |
| GIST | 64 | 同上 | 123,189 (77.0%) | 358 | 256 MB |
| Deep | 32 | 157,180/160,000 | 96,269 (60.2%) | 274 | 128 MB |
| Deep | 64 | 同上 | 151,890 (94.9%) | 112,856 | 256 MB |

原 F 精确扫描每 32 维检查一次部分平方和是否超过半径。按同样规则统计样本中的**坐标运算量**：GIST F 平均约 591 维/点；PCA 32 维过滤并对未排除点继续 F，约 296 维/点（50.0%），PCA 64 维约 265 维/点（44.7%）。Deep F 平均约 73.4 维/点；PCA 32 维组合约 64.9 维/点（88.5%），PCA 64 维组合约 68.8 维/点（93.8%）。这只是读/算坐标数模型，**不是 GPU 时延或端到端加速比**：尚未计入预投影构建、投影索引读流量、过滤器访存、精确扫描结果压缩和查询输出。尤其 Deep 的原始扫描已很早拒绝大部分点，PCA 更高剪枝率不意味着更低代价。

这种剪枝思路已有明确先例，不应把 PCA 安全下界本身作为创新点：D’haes 等的 [PCA branch-and-bound](https://www.sciencedirect.com/science/article/pii/S0167865502003847)（2003）用于精确 kNN 树搜索；Liu 等的 [progressive partial distance](https://www.sciencedirect.com/science/article/abs/pii/S0020025518305218)（2018）按主成分逐步累加精确安全下界；Chen 与 Güttel 的 [SNN](https://arxiv.org/abs/2212.07679)（2024）按第一主成分排序，对固定半径查询做精确剪枝；Ukey 等的 [HDR Tree](https://link.springer.com/article/10.1007/s11280-023-01204-9)（2023）明确使用投影距离作为树节点剪枝下界。它们的查询类型、索引和成本模型各不相同，不等于当前 GTS++ GPU 工作负载的端到端收益。

结论限于已测负载：相对给原树继续加全局枢轴，低维正交投影是更有潜力的精确过滤器，优先关注 GIST 32/64 维；但需要实现 GPU 两阶段扫描，与当前 F 在相同输出合同下正式对比。2026-09-25 检查时远端 8 张 GPU 均有其他进程占用，故本轮只完成 CPU 离线筛选，没有运行 GPU 测时。完整逐查询计数见 [`EVIDENCE.json`](EVIDENCE.json)，复现脚本见 [`screen.py`](screen.py)。
