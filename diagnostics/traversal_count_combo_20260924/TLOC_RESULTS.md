# Tloc 1M：消除融合路径的重复计数

在同一个 sm_120 二进制、同一张空闲 GPU 6、同一批 8 个查询上，四个进程轮次交替执行 E/P/R/Q。每个进程先预热 8 次，再测 8 次完整的 CUDA Graph 查询，时间包含 GPU 执行、同步和固定容量的 host 输出拷贝。结果按进程内 8 次查询的均值统计：

| 模式 | 遍历 | 重复计数阶段 | 四轮中位耗时 |
| --- | --- | --- | ---: |
| E | 原单线程块 | 保留 | 3.809 ms |
| P | 多线程块 | 保留 | 4.014 ms |
| R | 原单线程块 | 删除 | 1.228 ms |
| Q | 多线程块 | 删除 | 0.929 ms |

E/R = **3.103×**，R/Q = **1.321×**，E/Q = **4.099×**；这三项四轮均为 4/4 胜出。E/P 只有 2/4 胜出，P 呈明显双峰，不能单独声称多线程块在保留重复计数时稳定加速。E/Q 是这次实验直接观察到的完整查询比值，不是跨实验相乘。

R/Q 的完整输出都通过独立 CPU 距离/成员关系核对和原实现的有序 float32 结果哈希核对；两者输出文件 SHA-256 相同。R/Q 的 memcheck、synccheck 均通过。原始轮次、配对区间、GPU 状态和 22 个收据的哈希见 [TLOC_EVIDENCE.json](TLOC_EVIDENCE.json)。改动仍是实验驱动，未进入生产查询代码。
