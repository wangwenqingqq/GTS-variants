missing test third. The immediate priority is to identify the integrated

## 3. Evidence-recovery task R0 — mandatory, no GPU

**Gap sentence:** This fills §4.6 historical E1/E5 attribution; qualifying
evidence is missing because the draft/report lacks a complete raw-run identity.

Recover the original logs, trace and parameter files through the existing
evidence index; do not infer timestamps from migration mtimes. For each value,
record source/binary hashes, metric/data, original versus new IDs, buffer sizes,

## 4. Contract/compatibility task C0 — mandatory, no GPU

## 5. U0 — sequential correctness at original update boundaries

**Gap sentence:** This fills §3.3 acknowledged-update visibility and ID
semantics; qualifying evidence is missing because static queries and prepared
count probes do not certify complete update-prefix outputs.

### Frozen comparator and observation

- Pinned original GTS plus a separately named full-result observation adapter;
  register every modification. Raw original and routinely repaired original
  remain distinct configurations. Repair only after localizing a failure.
- First audit native insert/delete semantics. Native reinsertion of a base
  object does not prove new external-ID ingestion. If fresh arrivals require an
  API/loader adapter, name it and hash it; if that scope is not implemented,
  remove the strict-arrival claim rather than substituting duplicate IDs.
- Use a sequential active-set/multiset oracle with the registered ID convention.
  All positive/negative state checks count, not only returned result length.

### Minimal matrix

| Boundary | Query/check | Required output |
|---|---|---|
| Query-only / empty buffer | Zero-hit, exact-hit and all-hit | No stale count, full ID validity/membership |
| Insert→query | Existing native duplicate and, only under a declared arrival adapter, a new external ID | ACK-visible correct multiplicity/identity |
| Base delete→query | Included object, repeated delete if legal | Deleted identity excluded; other IDs unchanged |
| Buffer delete→query | First/last item; transition to empty buffer | Correct compacted buffer and zero buffer result |
| Rebuild threshold | Before threshold, exactly threshold, after rebuild | Same active membership across order/topology change |
| Delete+rebuild | Base tombstones plus pending buffer | No resurrected ID, dropped object or stale permutation |
| Bound/stride edge | Near/outside existing ancestor coverage, capacity boundary, tied distances | Sound full-path pruning and legal row stride |
| Repeated state | Several unchanged queries between updates | No workspace state leakage; unchanged outputs |

Start with the existing deterministic N1000, D128 native probes at legal tree
capacity; use the existing integer-distance oracle. They cover counts and must
be extended/observed for IDs to close the new claim. Add small edge fixtures
rather than immediately running million-object traces. Fresh-arrival fixtures
must be distinct from base and queries; register all hashes before timing.

Acceptance: zero invalid/duplicate/dropped IDs relative to the declared
multiset contract, zero range FN/FP under the exact reference, and passing
memcheck/synccheck on bounded representative original/repaired/candidate
boundaries. Count equality or a silent sanitizer is insufficient. Preserve the
first divergence and rejected run; no performance promotion before correctness.

## 6. Q0 — necessary integrated complete-query bridge

**Gap sentence:** This fills §4 integrated query benefit; qualifying evidence
is missing because historical gains come from different binaries/query sets.

Only if C0 produces a real range keeper, compare:

1. Original pinned GTS with declared capacity/full-output observation adapter.
2. Conventional repaired/tuned GTS: legal capacities, corrected aggregation,
   reasonable workspace; distinguish changed arithmetic from execution changes.
3. Integrated keeper with common IDs/arithmetic/output contract.
4. Strong batch scan, and the appropriate existing external range implementation
   if its membership/field gates pass. Do not describe a kNN API as native range.

Reuse representative prior configurations: GIST-1M×960D half and normal radius,
B32; Deep-1M×96D normal B32; Tloc-1M×2D B1 and B32. The positive half-radius case
and negative shallow/single-query cases must both remain. Do not optimize on a
held-out final set. If old final queries are reused for a bridge, disclose reuse;
any retuning uses development data and requires a fresh final set.

Freeze FP32 inputs, candidate membership convention, explicit distance/field
contract, query IDs/radius bit patterns, result order and actual-length delivery.
Any incompatibility with original math must be a named comparison, not a
layout-only ratio. Timed scope: ready batch submission through all valid IDs and
fields received at Host; include packing, tree, clear, count feedback, collection,
copy and synchronization. Separate build, refit, graph capture and cold setup.

Use six independent process rounds as in P4, eight registered development
warmups, alternating/rotating variant order and identical formal query order.
Report raw order, paired process ratios, median and ranges, full pass time and
batch p50/p95. Claim a robust separation only against the predeclared P4 1.03×
threshold; a smaller observed change is retained but not promoted. Correctness,
sanitizer and sustained repeated-query state checks are separate gates. No
single-keeper kernel-only result qualifies the bridge.

## 7. U1 — complete sequential query/insert/delete/maintenance replay

**Gap sentence:** This fills §4.6 dynamic end-to-end improvement; qualifying
evidence is missing because non-rebuild timing and rebuild counts omit deferred
query/maintenance cost and do not certify real update prefixes.

Run only if retaining C3 after C0/U0. Freeze one immutable trace and active-set
oracle for original, conventional repaired/tuned baseline and keeper. Compare a
reasonable-buffer baseline, not only original's ten-item threshold. Buffer
choice uses a separate development trace; final trace is never tuned.

Minimal staging: bounded replay with 10K base, a disjoint arrival pool and query
pool, 5K sequential events, registered 4:4:2 insert/delete/query mix, three seeds.
This staging is not a representative long-run speed claim. Use the smallest
legal tree configuration; do not transplant fixed height to a capacity it
cannot support. Native APIs that cannot implement fresh-ID arrivals are
reported as non-admitted, not coerced into an inequivalent duplicate trace.

After bounded validity, choose one representative long trace sufficient to
exercise multiple compactions/rebuilds and a skewed/clustered variant. Exact
lengths, initial state, delete selection, workload mix, radii/k and sampling must
be frozen in its contract before execution, justified by the target claim, not
chosen to obtain a maximum speedup. This plan does not launch them now.

Timed scope: whole serialized operation sequence including ACK, tree+buffer
query, delete filtering, compaction, rebuild, output and synchronization. Keep
query, insert, delete and rebuild stage totals as attribution; do not add
overlapping CPU API durations. Report throughput, query/update p50/p95/p99,
rebuild count/time, buffer/delta size over time, candidate work, memory peak and
output validity at every checked prefix. Report any rebuild availability pause.

Admission: same active set, quality, external IDs and ACK visibility; no FN/FP or
invalid IDs at correctness checkpoints. External systems are admitted only if
they implement this trace/metric/visibility contract; native versus wrapper
updates/rebuilds must be explicit. A CPU comparator is labeled with its hardware.
No concurrency, freshness relaxation or update work may silently disappear.

## 11. Deliverables and explicit non-goals

Each accepted experiment appends the existing P4 evidence ledger with source
entry, contract, raw manifest, absolute timings, same-contract denominator,
quality gate, positive result, negative boundary and allowed paper wording.
Large raw outputs stay outside Git with hashes and reproduction instructions.

Non-goals: all-GPU-tree prevalence claims, Tensor Core direction, multi-GPU,
concurrent transactions, new adaptive-pruning deployment, and rerunning every
historical dataset. Broader metric/application experiments are required only if
the eventual thesis retains that scope; the current measured components are
static L2 range mechanisms.
