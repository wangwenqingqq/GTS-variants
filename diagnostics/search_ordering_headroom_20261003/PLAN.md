**本轮先做理想上界与搜索顺序诊断；通过闸门后，才考虑MLP／Transformer。**  
冻结代码：`wangwenqingqq/GTS-variants@36d58aeb93844aec3febd17d9f9caf17b88601f0`。建议独立目录：`diagnostics/search_ordering_headroom_20261003/`。

## 0. 先接受最新去留结论，不用“加Transformer”绕过它

最新P7-GATE报告已记录 `STOP_CURRENT_KNN_PATH`：修复后的GIST1M×960、K8、B32、32条诊断查询上，O_MASK四轮Host-ready中位数133.049 ms，Faiss Flat为6.971 ms，同轮耗时比中位数19.09。独立剖析中距离核验126.939 ms，最终top-K与输出核4.118 ms。这些是既有测量，不是本方案的新结果。[R1]

因此，本轮不是宣布重启旧执行器，而是一个**有终点的机制可行性实验**：更早收紧第K近距离，究竟能减少多少“完成精确查询”所需的工作？若连诊断性的理想阈值也无法提供足够空间，停止当前树／边界下的学习排序，不继续训练模型。

当前P7在种子选K后生成一次cutoff，再遍历到固定前缀、做一次批量核验与最终top-K；源码没有在每批节点完成后更新cutoff的顺序搜索循环。[R2] 因而不能只改节点排列就声称在测试“先找到近邻、再收紧上界”：**必须将动态更新与排序策略分开对照。**

## 1. 两条必须纠正的推理

### 1.1 找到答案不等于完成精确查询

诊断oracle知道真实top-K，可以发现某时刻已经找到了答案；可部署程序仍须证明其余未访问对象不可能更近。必须分别记录：

- `hit_found`：离线看来，已取得合法的真实前K候选／已达到真实第K距离。
- `certified_done`：程序已有K个真实不同ID，且剩余所有工作被安全排除或核验完，最终结果已交付。

例子：前1000个对象就包含真实前8，但其余80万个对象所在节点的合法下界仍不够大。它们可能仍需核验。只报“1000个对象找到答案”不能证明查询只花1000个对象的成本。

### 1.2 “真top-K所在节点优先”不是全局最优排序证明

它是强诊断策略，不保证GPU时间最优。节点大小、局部性、查询间共享、检查与同步成本都能改变排序的效果。

本计划称其为 `ORACLE_FIRST`，不是“数学最优调度”。`U_STAR`则是把真实第K距离提前提供给固定执行器的理想阈值探针；它给出固定界、固定工作划分下的乐观候选／坐标工作量参照，**不是所有可能算法的时间下界**。不得因一条oracle策略失败，就断言所有学习排序不可能有效。

## 3. E0：最先做“理想第K距离”探针，不训练模型

### 3.1 生成离线真值

独立全表参考生成每条查询的原始ID top-K、精确参考平方距离 `U_star`、第K位并列信息。`U_star`只能存在于明确标识的diagnostic入口和离线标签，不可传入任何待报告部署版。

### 3.2 五种同二进制比较

| 模式 | 是否使用树 | 使用什么阈值 | 性质 |
|---|---|---|---|
| O_BOUND | 否 | 实际4096种子计算的U0 | 可部署、已有 |
| O_MASK | 是 | 同样U0 | 可部署、已有 |
| STAR_SCAN | 否 | 离线真实U_star | 非可部署诊断 |
| STAR_MASK | 是 | 离线真实U_star | 非可部署诊断 |
| FAISS_FLAT | 否 | 不用半径阈值 | 同质量强基线 |

STAR不直接输出oracle ID；仍执行真实距离／安全早退／完整GPU top-K和结果交付。保留种子计算及现有选择流程，避免把删掉种子阶段的收益误当阈值收紧收益。可在种子计算后增加统一的cutoff物化pass，普通／STAR均执行同一pass，仅运行时来源不同；原O_MASK不带该pass的桥接另记。

离线真值预先拷到设备的成本不计入STAR诊断，但必须标 `USES_ORACLE_NOT_DEPLOYABLE`。不能把STAR的Host-ready排进可部署方法速度榜。所有查询都保持相同数据、ID顺序、维度累加、掩码与数值安全规则；不能只对STAR放松边界。

### 3.3 必须测到的量

- 完整实际Host-ready、独立距离核时间、现有top-K时间、树/掩码时间。
- U0与U_star的差距；U_star=0时使用独立标记，不能随意除零。
- 对象候选对数、同微块候选并集、配对坐标更新数、共享坐标读取步数。
- 每查询在U_star下仍不能被当前树界排除的节点及对象比例。
- `STAR_SCAN→STAR_MASK`：阈值已经理想时，树是否还有价值。

E0预算：5模式×4轮=20个干净计时进程。全部逐次质量检查；profile和计数另跑。先完成这张表，不铺开训练集或重写在线搜索。

### 3.4 E0如何决定下一步

- STAR几乎不减少候选或距离时间：当前界／维度顺序下，收紧阈值不是主要出路。停止本轮学习排序。
- STAR_MASK仍超过Flat两倍耗时，且没有已验证的低成本执行底座：不以“训练Transformer救活当前P7”为理由继续。保留阈值敏感性与界失效的研究证据。
- STAR明显减少距离工作，并出现可用时间空间：允许进入离线排序模拟，仍不直接训练。

“2倍”和“明显”的具体研发阈值在YAML中冻结；它们不是论文标准或普遍不可能性定理。若希望研究新树界或新执行基础，应另立问题，而不是在此实验内无止境扩展。

## 4. E1：同一动态搜索逻辑，只改变先处理哪个节点

### 4.1 先构造可复核的节点表

导出固定停止层的**完整、不重叠、覆盖全库**的终端分区。树中提前终止的小分支也必须纳入，不能因为不到C4而漏掉。记录node_id、成员ID位置区间、大小、合法下界和枢轴距离；校验每个对象出现一次。

独立参考离线为每query/node计算局部真实top-K及必要边界信息，用于快速回放状态更新。预计算不计作搜索性能。它代替了模拟中的实际核验，但模拟须按本应核验的对象数、节点数收费，不能因为查了缓存就报微秒级搜索性能。

### 4.2 四种排序策略

| 策略 | 排序依据 | 能否部署 |
|---|---|---|
| INDEX_ORDER | 当前节点编号顺序 | 能 |
| LOWER_BOUND | 合法下界从小到大，节点大小／ID作为固定次级规则 | 能 |
| PIVOT_ORDER | 已计算的查询—枢轴距离从小到大 | 能 |
| ORACLE_FIRST | 优先当前可处理、包含参考前K的节点；同类按节点大小再ID | 不能，仅诊断 |

每种策略都使用同一4096种子初始化U、同一“每波4节点”、同一精确top-K合并、同一安全排除规则。**INDEX_ORDER也必须每波更新U**，否则“动态更新的收益”会被错误计为学习排序收益。

节点按现有几何空间覆盖，不存在因值相似便删除另一个节点的规则。模型或oracle给分只决定先后，不改变候选覆盖。

### 4.3 模拟循环

```text
计算相同种子候选，建立按真实距离排序的K个不同ID，得到U
pending = 所有尚未安全排除、且未处理的终端节点
while pending非空:
    用合法界排除 lower_bound > outward_radius(U) 的节点
    从剩余pending按当前策略取最多4个节点
    处理这些节点的全部尚未排除对象；模拟从局部参考表取得结果
    将新候选与已知K个候选按ID去重，再做真正top-K更新U
    标记本波节点完成；记录hit_found与certified_done的差别
在没有未处理/在途任务且覆盖证书成立时，输出K个结果
```

实际GPU版本不能调用局部oracle结果表；必须核验数据。lower_bound值为欧氏距离时与向外包围sqrt(U)比较，不把平方距离和欧氏距离混算。接近边界、不完整或非有限的界保守放行，不能用经验epsilon。模型预测的距离绝不成为上界；上界只来自真实计算的K个不同对象。

### 4.4 重点看两类工作

分别记录：

1. 第一次得到真实第K距离前的工作：`objects_before_true_U`、波次数。
2. 完成全库覆盖证明的总工作：`objects_total`、`nodes_total`、`verification_after_true_U`、候选并集、阈值曲线。

第一类大幅下降、第二类不降，说明主要问题是最终的排除证明而非找到好候选；不进入Transformer训练。

上述oracle优先策略并不是最优排序。结果只能说明这一诊断策略提供多少空间。必要时，使用E0真实U从一开始生效的固定界探针作为更强参照，不宣称全局最优。

## 5. E2：只有离线有空间，才做GPU分波回放

实现一个公共动态执行器，所有排序共用：种子、终端分区、候选表示、距离核、波内top-K、运行中top-K、同步与输出。先不变更精度或选择算法。

运行 `INDEX_DYNAMIC、LB_DYNAMIC、ORACLE_DYNAMIC`，同时对照静态O_MASK与Flat，仍是32查询/B32，四轮，最多20个计时进程。PIVOT策略只有开发模拟明显不同才替换或加入，预算变更须提前记录。

### 5.1 GPU必须保留的公平性

- 索引顺序与LB的实时排序/选择费用全部计入；ORACLE使用预生成优先级，只报理想顺序的实际执行成本，仍不是可部署端到端性能。
- 每波最多4节点/查询，所有方法一致；比较不能让oracle串行扫描小块、普通方法却一次扫描全库。
- B32仍保持Q_T=2，节点配对不同时取两查询需要数据的并集；使用原块和各自mask，不为了oracle免费重排向量。
- 维护未处理、已排除、已完成、在途状态；遗漏或重复的ID不能污染top-K。
- 种子可能落在随后访问的节点中，合并top-K时按原ID去重；不能用同一对象的重复记录凑够K、把U非法压小。
- 已知U只可单调不增，且必须由真实候选产生。多个流看到稍旧、较大的U最多多算；读到没有有效K候选支撑的较小U则可能错误剪枝，严禁。
- 如果采用CPU每波调度，所有设备回传与再次提交都算入；如果采用重复Graph启动，也算全部启动与计数检查，不把计划制定免费移到计时外。
- 每波动态更新top-K的新增成本、GPU空闲、任务量不均衡、失去的共享读取必须记录。

学习排序若只比一个低效的动态顺序器快、仍不如静态O_MASK或Flat，不构成竞争性收益。

## 6. E3：前两关通过后，才比较简单模型和Transformer

### 6.1 模型仅打分，不能删节点

第一版每次从完整pending中按**相同廉价规则**提出最多64个节点作为打分窗口。选取分数最高的4个先处理；没有入窗或没有被选中的节点继续保留在pending中，之后仍需被处理或由安全界排除。

为了判断窗口是否限制了模型：离线同时报告“看全部pending的ORACLE_FIRST”与“只看同一64窗口的ORACLE_64”。Transformer应与后者比较；不能拿一个只能看64节点的模型去追一个免费看到全库的oracle，并将差距误判为模型失败。

如果所有可见节点均安全排除或评分出现NaN/超时，回退LOWER_BOUND；不准因时间预算到期就返回未认证结果。

### 6.2 相同输入，比较规则、MLP和小Transformer

候选token仅使用搜索当时可计算的量：合法lower bound、已算pivot距离、log(节点大小)、深度、当前U、已核验数量、批内候选重叠统计、数据块占用率、已冻结的成本估计。

禁止使用：query真实top-K ID、node真实最小距离、测试oracle距离、完成后测到的耗时、测试命中标签。query_ID不能作为记忆答案的特征。任何特征生成、GPU/CPU拷贝均计时。

- MLP：逐节点相同输入，加可部署的全局汇总特征；两层32隐藏单元起步。
- Transformer：1层encoder、d_model=32、2 heads、FFN=64、最多64个节点token；不设位置编码去记节点遍历顺序，采用合法token mask。
- 不预先认定Transformer更好。若MLP或规则更快、质量相同，保留更简单方案。
- 第一轮不加RL、不做模型规模搜索、不用昂贵外部语言模型。

### 6.3 训练目标是搜索收益，不是“识别哪个节点属于top-K”本身

离线使用局部参考结果计算某状态中“先处理节点a后，真实U会下降多少、可额外排除多少剩余工作、节点核验成本多大”的标签。对相同状态的候选训练排序/回归，不把仅仅命中一个答案的分类准确率当最终指标。

oracle标签生成耗时和GPU资源单列，不计热查询但计入训练成本。状态来自固定规则与模型的训练集回放，验证/测试查询不参与状态采样或归一化拟合。可以一次补充训练集策略自身到访状态，不能在最终集在线反向训练。

初始规模：512条训练、128条验证、128条封存测试查询，ID彼此不重合且排除已有诊断/开发记录；同一查询的所有节点、所有状态只属于一个split。此规模只是首轮验证预算，不声称足够训练通用索引。

先单独计时未训练/固定权重的真实模型与特征管线，确认其开销小于规则与理想顺序之间的时间余量，再投入标签生成和训练。随机权重计时只证明成本，不证明效果。

## 7. 正确性和鲁棒性关卡

复用独立逐维FP64参考和合法同距并列规则。成员不能以容差放宽；返回字段沿用冻结kNN合同，并另报确定性ID召回与字段误差。

小表至少覆盖：重复向量、self、K边界并列、节点含种子、节点跨32对象包、节点为空、尾批不足32、所有界失效、全部界为0、最后一个节点才含真正近邻、查询相同／完全不同、U初始为0、错误/反序/随机/常数/NaN模型分数。

每个顺序都必须继续到覆盖认证完成；模型预测再差也不得丢弃未证明安全的节点。故意反序仍应返回相同合法答案，可能更慢。这个性质的前提是完整pending管理与保守数值界，不是“用了树”就自动获得。

在小数据检查所有节点下界是否覆盖其真实成员；遇到反例修复或退化为不剪，不把错误样例从测试集删除。B32验证共享掩码没有以交集代替并集。

## 8. 计时与收益账

主指标始终是 `T_certified_host_ready`：完整查询输入、特征／评分、树界、候选/任务整理、核验、每波top-K更新、最终排除检查、所有K答案返回及同步。

同时记录 `T_first_true_U`，但它仅为离线对照诊断，不能充当查询结束时间。

工作表至少含：候选对象对、微块并集、配对维度更新、共享坐标加载步数、波次、每波K更新、核启动次数、模型/特征时间、DRAM及指令、剩余认证工作、输出质量。

强对照为相同slice的Flat和最佳已测可部署非学习实现。不能只与较慢INDEX_DYNAMIC比较后宣称“Transformer加速”。所有加速比由同轮实际完整时间计算，oracle不得进入部署排名。

profile单独运行，不用节点级trace时长作正式分母。CUDA Graph节点级跟踪可以定位核，但可能引入显著开销；记录其与无profiler计时的桥接。[D3] 不将CPU等待和它等待的GPU活动重复相加。

## 9. 事前写好的停止规则

以下百分比是本轮研发筛选阈值，不是论文录用规则。

| 观察 | 决策 |
|---|---|
| E0理想阈值对候选/核验几乎无影响（预设<10%改善） | 当前界下不投入学习排序；查界质量／核验执行，另立问题 |
| E0诊断仍>2×Flat且无已验证新执行底座 | 不为救活当前P7训练模型，归档阈值敏感性 |
| 更早得到真实第K距离，但完整认证工作改善<10% | 停止基于“更快找答案”的排序主张 |
| ORACLE_FIRST没有赢规则 | 不证明所有排序无效；结合U_STAR判断；没有额外空间证据就不训练 |
| 理想顺序相对最佳规则完整时间至少低30%，且确有相应核验削减 | 才考虑小模型；留足预测与组织开销预算 |
| 模型特征＋推理开销超过理想可节省时间的25% | 优先更便宜规则/MLP，不扩大Transformer |
| 学习策略不能在封存集比最佳可部署规则至少快10%，或正确性失败 | 不保留Transformer贡献，保留可用简单规则/机制 |
| 内部收益存在，但整体仍显著落后Flat | 只保留组件/分析证据，不称通用检索器领先 |

模型错不漏检、理想顺序有收益、模型能学会、完整系统有竞争力，是四个不同问题。任一环节不能由上一环节自动推出。
